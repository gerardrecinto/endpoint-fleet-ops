What is real, and what is not verified.

Every claim on this page comes from a command that ran. Anything that did not run is listed on the right.

Verified

  • 9 tests pass. The osquery and policy queries run on SQLite with the same table and column names, and the API clients run against local stub servers.
  • scripts/macos-posture.sh ran on a real Mac and all four checks passed. shellcheck is clean.

Not verified

  • Nothing ran against a real Fleet, Intune or Jamf instance. Endpoints and fields come from their API docs.
  • The queries were not run in osquery itself, and a few columns differ by osquery version.
  • windows-posture.ps1 was not run (no Windows or PowerShell here).
  • Serial numbers are assumed to match across systems. Real fleets have blanks, case differences and virtual machines.

Questions before you try it.

Why do Fleet policies look inverted?

A Fleet policy passes when its query returns a row, so the policy query describes the good state. The osquery pack describes the bad state.

Can I run this against my fleet?

The API clients take a base URL and token. They were only tested against stubs, so try them read-only first.

Why SQLite for the tests?

osquery speaks SQLite SQL. Creating tables with the same columns checks syntax and logic without a device.
